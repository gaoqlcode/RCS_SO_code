## 1. 调用总图

产品 GUI 里一次 HRRP 的实际调用链：

```text
用户点「开始」
  → HrrpPage::onStart()                    // UI 线程
      填 HrrpParams，invokeMethod(startProcess)
  → HrrpWorker::startProcess()             // Worker 线程
      填 HrrpRequest，挂 Callbacks
      processHrrp(req, resp, cb, &err)     // librcs_proc
          MergeDat / 读 L0 / 脉压 / 定标 …
          cb.onCornerConfirm(...)          // 仍在 Worker 线程里同步调用
              emit needCornerConfirm(...)  // Queued → UI
              waitForSelection()           // Worker 阻塞
          ← UI: HrrpPage::onNeedCorner → provideSelection()
          继续写文件，填 resp
      emit hrrpReady / finishedOk
  → HrrpPage::onReady()                    // UI 画曲线
```

二次开发若不做完整 GUI，最少也要：

1. 工作线程调 `process*`  
2. 回调里能阻塞等到用户输入  
3. 路径 UTF-8

## 2. SDK 公开头怎么读

客户只应 include：

```cpp
#include "rcs/rcs.hpp"   // 拉齐 types / callbacks / rcs_api
```

| 文件 | 内容 |
|------|------|
| `sdk/include/rcs/rcs_api.h` | 函数声明：`process*`、`preview*`、探查、预览辅助 |
| `sdk/include/rcs/types.hpp` | `HrrpRequest` 等结构体、默认值、`namespace rcs` 枚举 |
| `sdk/include/rcs/callbacks.hpp` | `Callbacks` 里每个 `std::function` |
| `sdk/include/rcs/export.h` | `RCS_API` 导出宏 |

完整工程内部还会用 `lib/include/rcs/`（多拼接声明）。  
`pack_sdk` **不会**把 `lib/include` 覆盖进 `sdk/include`，避免客户头被污染。

### 2.1 请求默认值（看构造函数）

`types.hpp` 里例如：

```cpp
HrrpRequest()
    : pol("HH"), tgtName("目标"), sigmaTheoryDb(18.25),
      autoPick(false), cropN(8192), phaseMode(0)
{}
```

含义：

- 不写 `autoPick` → **必须**接 `onCornerConfirm`  
- `sigmaTheoryDb` 默认 18.25（角反理论 RCS）  
- `outDir` 空字符串 → 库内 `resolveOutDir` 生成 `处理结果_HRRP_<极化>`

其它业务同理：`RcsRequest::azMode` 默认聚束 `2`；`Sigma0Request::autoPick` 默认 `false`。

### 2.2 回调签名怎么对上

以 HRRP 为例，`callbacks.hpp`：

```cpp
std::function<bool(
    const std::vector<double> &,   // rangeM
    const std::vector<double> &,   // profileDb
    int,                           // peakIdx
    InteractSelection &            // 输出选点
)> onCornerConfirm;
```

实现里改 `sel.cornerRangeOverrideM`，`return true` 继续，`false` 取消。

RCS 的 `onCornerPick` 多了 `GrayImage` 和 `fullNr/fullNp`——选点坐标必须按这两个全分辨率尺寸来填，不能拿预览像素当 az/rg。

## 3. 库侧：以 processHrrp 为例

文件：`lib/src/hrrp/process_hrrp.cpp`（符号从动态库导出）。

### 3.1 入口形态

```cpp
bool processHrrp(const HrrpRequest &req, HrrpResponse &resp,
                 Callbacks &cb, std::string *err)
```

文件开头有小工具：

```cpp
static bool cancelled(Callbacks &cb) {
    return cb.isCancelled && cb.isCancelled();
}
static void progress(Callbacks &cb, int p, const std::string &m) {
    if (cb.onProgress) cb.onProgress(p, m);
}
```

所有长步骤之间都会查 `cancelled(cb)`，方便界面「取消」。

### 3.2 主流程（按代码顺序）

| 步骤 | 代码位置意图 | 进度大致 |
|------|----------------|----------|
| 解析输出目录 | `resolveOutDir` / `makeDirs` | — |
| 合并同极化 L0 | `MergeDat::mergeFolder` | ~10% |
| 读合并文件 | `Level0Dat::readFile` | ~30% |
| 去直流 / 直达波 | `Preprocess::*` | — |
| 脉冲压缩 | `PulseCompress` | — |
| 定标 / 角反峰 | `Calibration` 等 | — |
| **交互** | `cb.onCornerConfirm`（`autoPick==false`） | — |
| 写 pdat / 三级 hrrp | `Level2Pdat` / `Level3Text` | ~90% |
| 填 `resp.rangeM/rcsDbsm/...` | 供界面画图 | 100% |

读代码时顺着 `#include` 进：

- `lib/src/io/MergeDat.*`、`Level0Dat.*`  
- `lib/src/signal/Preprocess.*`、`PulseCompress.*`、`Calibration.*`  

RCS / 点频 / σ⁰ 各有 `lib/src/<模块>/process_*.cpp`，套路相同：**填 resp + 调回调 + 写文件 + 查取消**。

### 3.3 autoPick 分支

库内会判断 `req.autoPick`：

- `false`：调用对应回调；回调 `false` → 整函数 `false`  
- `true`：跳过弹窗，用自动峰 / 预填 ROI（CLI 冒烟用）

产品 GUI 的 Worker 里写死 `req.autoPick = false`，不要改成 true 除非做批处理工具。

## 4. GUI 线程骨架：ProcessWorker

文件：

- `gui/common/ProcessWorker.h`  
- `gui/common/ProcessWorker.cpp`  

### 4.1 职责

| 能力 | 实现要点 |
|------|----------|
| 取消 | `std::atomic<bool> cancel_`；`requestCancel()` 置位并 `wakeAll` |
| 等人选点 | `waitForSelection` + `QWaitCondition` |
| UI 回填 | `provideSelection(UserSelection)` |
| 进度 | `emitProgress` → signal `progress` |

### 4.2 waitForSelection（核心）

```cpp
bool ProcessWorker::waitForSelection(UserSelection &out)
{
    QMutexLocker lk(&mutex_);
    haveSelection_ = false;
    while (!haveSelection_ && !cancel_.load())
        selectionCv_.wait(&mutex_);
    if (cancel_.load())
        return false;
    out = selection_;
    haveSelection_ = false;
    return true;
}
```

Worker 在**库回调里**调用这个函数 → 线程卡住，直到 UI 调 `provideSelection` 或 `requestCancel`。

### 4.3 为什么 provideSelection 必须直接调用

`HrrpPage::onNeedCorner` 末尾注释写得很清楚：

```cpp
// 必须直接调用：Worker 阻塞在 waitForSelection，QueuedConnection 无法执行
worker_->provideSelection(sel);
```

若用 `QueuedConnection` 把 `provideSelection` 丢回 Worker 队列，Worker 正堵在 `wait` 里不跑事件循环 → **死锁**。

`requestCancel` 也刻意做成可从任意线程直接调（改 atomic + wake），不要 Queued 到忙 Worker。

### 4.4 clearSelectionWait

每次 `startProcess` 开头调用，清掉上次的选点标志和 cancel，避免二次运行状态脏。

## 5. Qt ↔ 库：RcsApiQt.h

文件：`gui/common/RcsApiQt.h`（几乎全是 inline）。

| 函数 | 作用 |
|------|------|
| `qs` / `ss` | `std::string` ↔ `QString`（UTF-8） |
| `grayToQImage` | `GrayImage` → `QImage::Format_Grayscale8` |
| `toQV` | `vector<double>` → `QVector<double>` |
| `toLibSel` | 界面 `UserSelection` → 库 `InteractSelection` |

路径不要用 `toLocal8Bit()` 之类，和库约定不一致（尤其 Windows 中文路径）。

`UserSelection` 定义在 `gui/common/Types.h`，是 Qt 侧结构；库侧是 `InteractSelection`，由 `toLibSel` 桥接。

## 6. HRRP 页：Page + Worker 逐段

### 6.1 文件分工

| 文件 | 角色 |
|------|------|
| `gui/modules/hrrp/HrrpPage.h/.cpp` | 控件、连信号、弹窗、画图 |
| `gui/modules/hrrp/HrrpWorker.h/.cpp` | 组请求、挂回调、调 `processHrrp` |

其它业务页同一模式：`XxxPage` + `XxxWorker`。

### 6.2 构造里建线程（HrrpPage 构造后半段）

```cpp
thread_ = new QThread(this);
worker_ = new HrrpWorker;
worker_->moveToThread(thread_);
connect(thread_, &QThread::finished, worker_, &QObject::deleteLater);

connect(worker_, &HrrpWorker::progress, log_, &LogProgressPanel::setProgress);
connect(worker_, &HrrpWorker::message, log_, &LogProgressPanel::appendLog);
connect(worker_, &HrrpWorker::needCornerConfirm, this, &HrrpPage::onNeedCorner,
        Qt::QueuedConnection);   // 回调在 Worker，槽在 UI
connect(worker_, &HrrpWorker::hrrpReady, this, &HrrpPage::onReady);
// ...
thread_->start();
```

要点：

- Worker **活在** `thread_`，不要在 UI 线程直接调 `startProcess`  
- `needCornerConfirm` 用 **QueuedConnection**：跨线程把曲线数据交给 UI 弹窗  

### 6.3 路径区：数据文件夹 + OutDirField

构造里（RCS / 点频 / σ⁰ / 拼接同型）：

```cpp
outDir_ = new OutDirField(this);
pathLay->addLayout(outDir_->createRow(pathBox));
outDir_->setPlaceholderHint(QStringLiteral("数据文件夹"),
                            QStringLiteral("HRRP_<极化>"));
```

`onDataFolderChanged` → `outDir_->resetFromBase(path, hrrpResultTag(pol))`；  
极化变更 / 点开始前 → `outDir_->refresh(...)`；  
提交参数 → `p.outDir = outDir_->text()`。

细则与库侧标记表见 [`源码导读.md` §2](源码导读.md#2-输出目录怎么统一必读)。

### 6.4 onStart：从按钮到 Worker

```cpp
void HrrpPage::onStart()
{
    // 校验文件夹、同步 SharedDataSession
    refreshDefaultOut();   // OutDirField::refresh
    HrrpParams p;
    p.dataFolder = folderEdit_->text().trimmed();
    p.outDir = outDir_->text();
    // ... pol / sigma / crop
    worker_->setParams(p);
    setBusy(true);
    QMetaObject::invokeMethod(worker_, "startProcess", Qt::QueuedConnection);
}
```

`setParams` 在 UI 线程写参数；`startProcess` 投递到 Worker 线程执行。  
注意 `setParams` 与 `startProcess` 不要并发乱改（本界面用 `setBusy` 禁重复点开始）。

### 6.5 HrrpWorker::startProcess 逐段

```cpp
void HrrpWorker::startProcess()
{
    clearSelectionWait();

    HrrpRequest req;
    req.dataFolder = ss(params_.dataFolder);  // QString → UTF-8
    // ...
    req.autoPick = false;                     // 强制交互

    Callbacks cb;
    cb.onProgress = [this](int p, const std::string &m) {
        emitProgress(p, qs(m));               // → UI 进度条
    };
    cb.isCancelled = [this]() { return isCancelled(); };

    cb.onCornerConfirm = [this](auto &R, auto &profileDb, int peakIdx,
                                InteractSelection &sel) {
        emit needCornerConfirm(toQV(R), toQV(profileDb), peakIdx);
        emit needUserInput(...);
        UserSelection qsel;
        if (!waitForSelection(qsel))          // 堵在这里
            return false;
        sel = toLibSel(qsel);
        return true;
    };

    HrrpResponse resp;
    std::string err;
    if (!processHrrp(req, resp, cb, &err)) {
        // 区分取消 / 失败，发 finishedCancelled 或 errorOccurred
        return;
    }

    HrrpResult result;
    result.rangeM = toQV(resp.rangeM);
    result.rcsDbsm = toQV(resp.rcsDbsm);
    // ...
    emit hrrpReady(result);
    emit finishedOk();
}
```

读这段时抓住三件事：

1. **所有库调用都在 Worker**  
2. **回调里 emit + wait**，不要在回调里直接 `QDialog::exec`（线程不对）  
3. **成功才**把 `resp` 转成 Qt 类型发出去  

### 6.5 onNeedCorner：UI 侧补完交互

```cpp
void HrrpPage::onNeedCorner(const QVector<double> &R,
                            const QVector<double> &profileDb, int peakIdx)
{
    plot_->setData(R, profileDb);             // 先画峰附近曲线
    const double sug = ... R[peakIdx] ...;
    bool ok = false;
    const QString text = QInputDialog::getText(...);  // UI 线程模态框

    UserSelection sel;
    if (ok && !text.trimmed().isEmpty())
        sel.cornerRangeOverrideM = text.toDouble();
    else if (ok)
        sel.cornerRangeOverrideM = -1;        // 回车：用自动峰
    else {
        worker_->requestCancel();             // 用户取消对话框
        sel.cornerRangeOverrideM = -1;
    }
    worker_->provideSelection(sel);           // 唤醒 Worker
}
```

`cornerRangeOverrideM < 0` 的语义与库约定一致：沿用自动峰。

### 6.6 onReady

```cpp
void HrrpPage::onReady(const HrrpResult &result)
{
    plot_->setData(result.rangeM, result.rcsDbsm);
    // 日志里可打 hrrpPath / pdatPath
}
```

## 7. RCS Worker：双选点回调

文件：`gui/modules/rcs/RcsWorker.cpp`。

与 HRRP 不同：连续两次交互。

```cpp
cb.onCornerPick = [this](..., const GrayImage &preview, int fullNr, int fullNp,
                         InteractSelection &sel) {
    emit needCornerPick(toQV(R), grayToQImage(preview), fullNr, fullNp);
    UserSelection qsel;
    if (!waitForSelection(qsel) || qsel.corners.isEmpty())
        return false;
    sel = toLibSel(qsel);
    return true;
};

cb.onTargetPick = [this](..., int modeHint, InteractSelection &sel) {
    emit needTargetPick(...);
    UserSelection qsel;
    if (!waitForSelection(qsel))
        return false;
    sel = toLibSel(qsel);   // 含 targetMode / targets / extendedRanges
    return true;
};
```

Page 侧槽函数负责：

1. 显示 `QImage` 预览（`InteractiveImageWidget` 等）  
2. 把用户点击转成 **全分辨率** `az/rg`  
3. `provideSelection`  

若只把预览像素写进 `InteractPick`，定标位置会偏——这是对接时最常见的 bug。

成功后组装 `RcsResultBundle`（路径 + `targets[]` + 可选剖面）`emit rcsReady`。

## 8. 后向散射 Worker：框选回调

文件：`gui/modules/sigma0/Sigma0Worker.cpp`。

```cpp
req.autoPick = false;

cb.onRectRoi = [this](const GrayImage &g, int fullNr, int fullNa,
                      const std::string &stage, RectRoi &out) {
    emit needRectRoi(grayToQImage(g), fullNr, fullNa, qs(stage));
    UserSelection qsel;
    if (!waitForSelection(qsel) || qsel.rectRois.isEmpty())
        return false;
    const QRect &r = qsel.rectRois.first();
    out = RectRoi(r.x(), r.y(), r.width(), r.height());
    return out.valid();
};

cb.onTargetRois = [this](..., std::vector<RectRoi> &outs) {
    // 可多个 QRect → 多个 RectRoi
};
```

Page / `RectPickDialog` 侧应：

1. `loadImagedRawPreview` 或用回调自带 preview  
2. 用户在预览上拖矩形  
3. **`mapPreviewRoiToFull`** 转成全分辨率再放进 `UserSelection.rectRois`  
4. `provideSelection`

`stage` 字符串：`"noise"` / `"cal"` / `"bg"`，UI 可用来换提示文案。

RAW 布局：`[Nr]行 × [Na]列`，见 `loadImagedRawPreview` / `processSigma0` 注释；读反会像噪声。

## 9. SDK gui_demo：BlockingQueuedConnection

产品 GUI 用「emit + waitForSelection」；demo 用另一种等价写法，更短。

### 9.1 ConfirmBridge（活在 UI 线程）

`sdk/demo/gui_demo/ConfirmBridge.cpp`：

```cpp
bool ConfirmBridge::askCornerConfirm(double suggestedM)
{
    bool ok = false;
    const double v = QInputDialog::getDouble(..., suggestedM, ..., &ok);
    if (!ok) return false;
    lastRangeM_ = v;
    return true;
}
```

### 9.2 DemoWorker 回调里阻塞切 UI

`sdk/demo/gui_demo/DemoWorker.cpp`：

```cpp
cb.onCornerConfirm = [this](..., InteractSelection &sel) -> bool {
    bool accepted = false;
    const bool invoked = QMetaObject::invokeMethod(
        bridge_, "askCornerConfirm",
        Qt::BlockingQueuedConnection,          // Worker 卡住等到 UI 跑完槽
        Q_RETURN_ARG(bool, accepted),
        Q_ARG(double, suggest));
    if (!invoked || !accepted)
        return false;
    sel.cornerRangeOverrideM = bridge_->lastRangeM();
    return true;
};
```

对比：

| 方式 | 用在 |
|------|------|
| emit + `waitForSelection` + `provideSelection` | 产品 `gui/modules/*` |
| `BlockingQueuedConnection` + Bridge | `sdk/demo/gui_demo` |

两种都可以；二次开发二选一即可，不要混用乱套导致双重等待。

### 9.3 demo 里探查 / 预览

同文件 `runProbe` / `runPreview`：

- 不需要选点回调，只挂 `onProgress` / `isCancelled`  
- `preview` 限制 `maxFiles = 8`，避免 demo 一次读太多

## 11. CMake / 打包 / deploy

### 11.1 根 `CMakeLists.txt`

- `RCS_USE_SDK=ON`：`IMPORTED` 链 `sdk/lib`，拼接触发关，不编 `lib/`  
- `OFF`：`add_subdirectory(lib)`，按是否有静态 tiff 决定 mosaic  

### 11.2 `gui/CMakeLists.txt`

- 源文件列表含各 `modules/*`  
- mosaic 源文件仅在 `RCS_ENABLE_MOSAIC` 时加入  
- Windows：`resources/rcs.rc` 嵌 `app.ico`  
- include：`${RCS_PUBLIC_INCLUDE_DIR}`（SDK 或 `lib/include`）  

### 11.3 `sdk/pack_sdk.sh` / `.bat`

- 只拷动态库到 `sdk/lib`  
- **不**覆盖 `sdk/include`  
- Windows 要同时认 `librcs_proc.dll` 与 `rcs_proc.dll`  

### 11.4 一键脚本与 deploy

- `scripts/build_linux.sh`：编 `rcs_proc` → pack → 编全量 → **`deploy_linux.sh`**  
- `scripts/build_win.ps1`：同上，并先杀占用 DLL 的进程 → **`deploy_win.ps1`**  

发布目录（整夹可拷贝运行）：

| 平台 | 目录 | 启动 |
|------|------|------|
| Linux | `deploy/linux_<arch>/` | `./run_RCS.sh` |
| Windows | `deploy/win64/` | `RCS.exe` |

内容含：GUI/CLI、`librcs_proc`、Qt 插件/DLL、MinGW 运行时（Win）。  
单独重打：`./scripts/deploy_linux.sh` 或 `.\scripts\deploy_win.ps1`。

## 12. 改代码时怎么下手

| 你想改… | 优先看 |
|---------|--------|
| 算法/定标/脉压 | `lib/src/signal/*`、`lib/src/<业务>/process_*.cpp` |
| 默认输出目录名/标记 | `gui/common/OutPath.h` **与** `lib/src/common/OutPath.h`（两边同步） |
| 输出目录交互逻辑 | `gui/common/OutDirField.*`（勿在各 Page 再抄一份） |
| 对外接口字段 | 同时改 `lib/include/rcs/*` 与 `sdk/include/rcs/*`（客户头） |
| 界面交互流程 | `gui/modules/<业务>/*Worker.cpp` + 对应 `*Page.cpp` |
| 线程/取消卡死 | `ProcessWorker.cpp`、Page 里 `provideSelection` 是否直接调用 |

## 13. 信号处理与 IO 源码片段

### 13.1 点频必须用 `removeDcPerPulse`

```cpp
// lib/src/signal/Preprocess.cpp
void Preprocess::removeDcPerPulse(ComplexMatrix &data)
{
    for (int p = 0; p < data.np; ++p) {
        std::complex<double> m{0, 0};
        for (int g = 0; g < data.nr; ++g)
            m += data.at(g, p);
        m /= static_cast<double>(imax(1, data.nr));
        for (int g = 0; g < data.nr; ++g)
            data.at(g, p) -= m;
    }
}

// lib/src/cw_rcs/process_cw_rcs.cpp
Preprocess::removeDcPerPulse(data);   // 勿改成 removeDc
```

## 14. 输出目录：OutDirField

### 14.1 为何单独抽出来

原先 RCS / HRRP / 点频 / 拼接各自维护 `outDirUserEdited_`、`lastAutoOut_`、`refreshDefaultOut`、`onBrowseOut`，后向散射甚至只靠「空则库内默认」、界面不自动填。  
现统一为：

| 文件 | 职责 |
|------|------|
| `gui/common/OutPath.h` | `defaultResultDir`、`*ResultTag`、`baseDirOfInput`、`resolveOutDir` |
| `lib/src/common/OutPath.h` | 同名规则（`std::string`），`process*` 用 |
| `gui/common/OutDirField.*` | 一行 UI + 自动/手改/浏览状态机 |

### 14.2 状态机（读代码时记住三句）

```text
resetFromBase  → 输入路径变了：强制写默认输出
refresh        → tag 变了或点开始：未手改才更新
textEdited/浏览 → userEdited=true，保护用户路径
```

### 14.3 Page 侧最小用法

```cpp
// 构造
outDir_ = new OutDirField(this);
pathLay->addLayout(outDir_->createRow(pathBox));
outDir_->setPlaceholderHint(QStringLiteral("数据文件夹"), QStringLiteral("RCS_<极化>"));

// 输入变更
outDir_->resetFromBase(dataFolder, rcsResultTag(pol));

// 提交
p.outDir = outDir_->text();
```

σ⁰：`resetFromBase(baseDirOfInput(rawPath), sigma0ResultTag())`。  
完整说明与动手练习见 [`源码导读.md` §2 / §10](源码导读.md)。
