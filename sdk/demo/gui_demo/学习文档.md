# gui_demo 学习文档：从头写出一个 SDK 界面壳

本文按「从零搭起」的顺序讲解 `sdk/demo/gui_demo`。目标不是复述每一行语法，而是讲清：**为什么要这样拆文件、线程和回调怎么接、界面怎么调 SDK**。读完后你应能自己改成 RCS / 点频 / 后向散射页。

配套源码（建议对照打开）：

| 文件 | 角色 |
|------|------|
| `CMakeLists.txt` | 链 Qt5 + `librcs_proc` |
| `main.cpp` | 进程入口、注册跨线程类型 |
| `SimplePlotWidget.*` | 简易折线图（可换成别的图库） |
| `ConfirmBridge.*` | 住在 UI 线程的弹窗桥 |
| `DemoWorker.*` | 后台线程：填请求、挂 `Callbacks`、调库 |
| `MainWindow.*` | 控件 + 线程生命周期 + signal/slot |

接口说明见 `../../接口使用说明.md`，头文件入口 `#include "rcs/rcs.hpp"`。

---

## 0. 这个 demo 要证明什么

甲方或二次开发时，界面一般自己做。SDK 只负责：

1. 填 `*Request`
2. 挂 `Callbacks`（进度、取消、选点）
3. 调 `process*` / `preview*` / `probe*`
4. 用返回的 `vector` / 路径自己画图、写日志

库**不会**创建窗口。难点在于：

- 库可能跑很久 → 必须在**工作线程**调用，否则界面卡死
- 进度、曲线要回到**UI 线程**改控件
- 选点回调在库线程里被同步调用 → 要**阻塞切回 UI 弹窗**，用户点完再 return

`gui_demo` 用最小 Qt 代码把这三条跑通，只演示：扫极化、探查、0 级预览、HRRP（含确认峰距）。

```
┌──────────── UI 线程 ────────────┐     ┌────── Worker 线程 ──────┐
│ MainWindow / ConfirmBridge      │     │ DemoWorker              │
│ 按钮 → invokeMethod(Queued)  ───┼────►│ runProbe / runPreview / │
│ ◄── signal: progress / done     │     │ runHrrp                 │
│                                 │     │   Callbacks → 调 SDK    │
│ ConfirmBridge::askCornerConfirm │◄────┤ onCornerConfirm 里      │
│   (BlockingQueuedConnection)    │     │ BlockingQueued 弹窗     │
└─────────────────────────────────┘     └─────────────────────────┘
```

## 1. 先搭工程骨架（CMakeLists.txt）

思路：demo **只依赖已打包的 SDK**，不编工程里那套完整 `gui/`。

要点：

1. `CMAKE_AUTOMOC ON` —— 有 `Q_OBJECT` 的类要 moc
2. `RCS_SDK_ROOT` 默认 `../..`（即 `sdk/`）
3. `find_library(rcs_proc … PATHS ${RCS_SDK_ROOT}/lib)`
4. `find_package(Qt5 COMPONENTS Core Gui Widgets)`
5. `BUILD_RPATH` 指向 SDK 的 `lib`，运行时少设一点 `LD_LIBRARY_PATH`

编译顺序（仓库根）：

```bash
cmake --build build_linux -j --target rcs_proc   # 或你的 build 目录
./sdk/pack_sdk.sh

cd sdk/demo/gui_demo
cmake -S . -B build
cmake --build build -j
./build/rcs_gui_demo
```

Windows 用 `WIN32` 子系统 + `Qt5::WinMain`，避免黑控制台窗口。

## 2. 入口：main.cpp（最短）

```cpp
QApplication app(argc, argv);
qRegisterMetaType<PreviewBundle>("PreviewBundle");
qRegisterMetaType<QVector<PreviewBundle> >("QVector<PreviewBundle>");
MainWindow w;
w.show();
return app.exec();
```

为什么注册元类型？  
`DemoWorker` 会 `emit previewDone(QVector<PreviewBundle>)`，信号跨线程排队时，Qt 要能拷贝/识别这个类型。自定义结构体必须 `Q_DECLARE_METATYPE` + `qRegisterMetaType`，否则连接可能失败或运行时报错。

`main` 里**不**调 SDK，只起 UI 事件循环。

## 3. 第一步自己画曲线：SimplePlotWidget

正式产品常接 QCustomPlot、Qt Charts 等。demo 故意手写一个 `QWidget`：

- `setData(x, y)` 存两路 `QVector<double>`，然后 `update()`
- `paintEvent` 里算数据范围，映射到绘图矩形，`drawPolyline`
- `setYRange` 可锁纵轴（频域图锁在 -60~3 dB）

写界面时先完成「SDK 的 `vector` → `QVector` → `setData`」，图画出来再去抠算法。

把库的 `std::vector<double>` 拷成 Qt 容器的惯用写法（见 `DemoWorker.cpp`）：

```cpp
QVector<double> copyVec(const std::vector<double> &v) {
    QVector<double> o;
    o.reserve((int)v.size());
    for (size_t i = 0; i < v.size(); ++i) o.push_back(v[i]);
    return o;
}
```

路径一律 UTF-8：`QString::toUtf8()` → `std::string`，回来用 `QString::fromUtf8`。

## 4. 第二步：确认峰距桥 ConfirmBridge

HRRP 默认 `autoPick=false`，库会在处理到「核对角反峰」时调用：

```text
Callbacks::onCornerConfirm(rangeM, profileDb, peakIdx, InteractSelection &sel)
```

这个函数在**库所在线程**（Worker）里同步执行。若在这里直接 `QInputDialog`，会违反「只在 UI 线程碰控件」的规则，轻则警告，重则崩溃。

做法：

1. `ConfirmBridge` 作为 `QObject`，**父对象挂在 MainWindow 上** → 住在 UI 线程
2. Worker 的 `onCornerConfirm` 里：

```cpp
bool accepted = false;
QMetaObject::invokeMethod(
    bridge_, "askCornerConfirm",
    Qt::BlockingQueuedConnection,   // 关键：阻塞 Worker，直到 UI 槽返回
    Q_RETURN_ARG(bool, accepted),
    Q_ARG(double, suggest));
if (!accepted) return false;
sel.cornerRangeOverrideM = bridge_->lastRangeM();
return true;
```

3. `askCornerConfirm` 里真正弹 `QInputDialog`，把用户输入的距离存进 `lastRangeM_`

`BlockingQueuedConnection` 含义：

- 把调用投递到 bridge 所在线程（UI）
- **当前线程（Worker）卡住等待**
- UI 处理完槽函数，返回值拷回，Worker 继续跑库

取消对话框 → `return false` → 库当作用户取消，`processHrrp` 返回 false。

扩展其它业务时，同一套路：

| 业务 | 回调 | Bridge 槽可做成 |
|------|------|-----------------|
| RCS | `onCornerPick` / `onTargetPick` | 在灰度图上点选，写 `InteractPick` |
| 点频 | `onCornerConfirm` + `onTargetPick` | 同上 |
| 后向散射 | `onRectRoi` / `onTargetRois` | 框选矩形，注意全分辨率坐标 |

## 5. 第三步：只调库的 DemoWorker

原则写在头文件注释里：**只调库，不碰控件；进度/结果用 signal 回主线程。**

### 5.1 成员

```cpp
std::atomic<bool> cancel_;   // UI 点「取消」时置位
ConfirmBridge *bridge_;      // 不拥有，只借用指针
```

`requestCancel()` 很轻，可从 UI 线程直接调（原子变量）。库通过 `cb.isCancelled` 轮询。

### 5.2 探查 runProbe（无 Callbacks）

探查 API 同步、较快，不强制 Callbacks：

```cpp
L0FolderProbe p;
if (!probeDataFolder(folder, pol, p, &err)) { emit failed(...); emit finished(); return; }
// 拼一段给人看的文字
emit probeDone(text);
emit finished();
```

`finished` 用来让 MainWindow `setBusy(false)`，按钮恢复可点。

### 5.3 预览 runPreview

```cpp
L0PreviewRequest req;
req.dataFolder = ...;
req.pol = ...;
req.maxFiles = 8;   // demo 只算前 8 个，避免卡太久

Callbacks cb;
cb.onProgress = [this](int p, const std::string &m) { emit progress(p, fromUtf8(m)); };
cb.onMessage  = [this](const std::string &m) { emit logMessage(fromUtf8(m)); };
cb.isCancelled = [this]() { return cancel_.load(); };

previewL0Folder(req, resp, cb, &err);
// 把 resp.items 转成 QVector<PreviewBundle>，emit previewDone
```

这里体现了 SDK 约定：

- `onProgress` / `onMessage` 里**不要**直接改控件，只 `emit`；Qt 会排队到 UI 线程
- `isCancelled` 读原子标志，库在循环里检查

`PreviewBundle` 是 demo 自己的「可进信号」结构，字段对应 `L0PulsePreviewItem` 的子集。

### 5.4 HRRP runHrrp（带选点）

```cpp
HrrpRequest req;
req.dataFolder / outDir / pol = ...;
// autoPick 默认 false，必须实现 onCornerConfirm

Callbacks cb;
// 进度、取消同上
cb.onCornerConfirm = [this](..., InteractSelection &sel) -> bool {
    // BlockingQueued → ConfirmBridge
    sel.cornerRangeOverrideM = bridge_->lastRangeM();
    return true; // 或 false 取消
};

processHrrp(req, resp, cb, &err);
emit hrrpDone(resp.hrrpPath, rangeM, rcsDbsm);
```

成功后界面用 `rangeM` / `rcsDbsm` 画 HRRP 曲线，路径写到标签。文件落盘由库完成（`.hrrp` / `.pdat` / 1 级 `.dat`）。

## 6. 第四步：MainWindow 拼界面 + 接线程

建议按构造函数里的顺序理解。

### 6.1 搭控件

上半：输入目录、输出目录、极化下拉、「扫一下极化」。  
按钮：探查 / 预览 / 跑 HRRP / 取消。  
左：探查文字、日志、进度条。  
右：时域 / 频域 / HRRP 三张 `SimplePlotWidget`，以及上一个/下一个切换预览文件。

这些都是普通 Qt 布局，与 SDK 无关。

### 6.2 创建线程与 Worker（核心）

```cpp
confirmBridge_ = new ConfirmBridge(this);  // 父对象=this → UI 线程

thread_ = new QThread(this);
worker_ = new DemoWorker;                  // 先无 parent
worker_->setConfirmBridge(confirmBridge_);
worker_->moveToThread(thread_);            // 之后槽在 Worker 线程执行
connect(thread_, &QThread::finished, worker_, &QObject::deleteLater);
thread_->start();
```

注意：

- Worker **不要** `new DemoWorker(this)` 再 `moveToThread`，父子线程不一致会出问题；先无父对象再 move
- Bridge **不要** move 到 Worker，否则弹窗又跑错线程

### 6.3 连接 signal → UI

```cpp
connect(worker_, &DemoWorker::progress, this, [](int p, const QString &m) {
    bar_->setValue(p);
    log_->append(m);
});
connect(worker_, &DemoWorker::previewDone, this, [this](const QVector<PreviewBundle> &items) {
    previewItems_ = items;
    showPreviewIndex(0);
});
connect(worker_, &DemoWorker::hrrpDone, this, [...]{ hrrpPlot_->setData(R, rcs); });
connect(worker_, &DemoWorker::finished, this, [this]() { setBusy(false); });
```

跨线程默认 `AutoConnection`：发射方在 Worker、接收方在 UI → 实际是 Queued，安全。

### 6.4 按钮如何「派活」给 Worker

不要直接 `worker_->runHrrp(...)`（那会在 UI 线程执行）。用排队调用：

```cpp
setBusy(true);
QMetaObject::invokeMethod(worker_, "runHrrp", Qt::QueuedConnection,
    Q_ARG(QString, folder), Q_ARG(QString, out), Q_ARG(QString, pol));
```

对应槽必须是 `public slots:`，且类型已注册（`QString` 内建即可）。

`setBusy(true)` 禁用探查/预览/HRRP，启用取消；`finished` 再解开。

### 6.5 扫极化为什么可以在 UI 线程

`listAvailablePolarizations` 只扫文件名，很快，demo 直接在 `onRefreshPol` 里调。若目录极大，也可丢进 Worker。

### 6.6 析构

```cpp
worker_->requestCancel();
thread_->quit();
thread_->wait(3000);
```

先请求取消，再停事件循环，避免关窗时库还在跑。

## 7. 三条业务时序（对着代码走一遍）

### 7.1 探查

```
用户点「探查」
  → MainWindow::onProbe
  → invokeMethod(runProbe, Queued)
  → DemoWorker::runProbe
  → probeDataFolder(...)
  → emit probeDone(文字) → infoLabel_
  → emit finished → setBusy(false)
```

### 7.2 预览

```
用户点「预览」
  → runPreview
  → previewL0Folder + Callbacks(进度/取消)
  → 转 PreviewBundle 列表
  → emit previewDone
  → MainWindow 缓存 previewItems_，showPreviewIndex(0)
用户点「上一个/下一个」→ 只改显示，不再调库
```

### 7.3 HRRP + 确认峰距（最重要）

```
用户点「跑 HRRP」
  → runHrrp（Worker 线程）
  → processHrrp(...)
       库内部合并/读数/脉压…
       需要确认峰时调用 onCornerConfirm
         → invokeMethod(askCornerConfirm, BlockingQueued)
         → UI 线程弹出 QInputDialog，用户确认
         → 返回 Worker，写入 sel.cornerRangeOverrideM
       继续裁剪、写 .hrrp/.pdat…
  → emit hrrpDone(path, R, rcs)
  → hrrpPlot_->setData
  → finished
```

取消：

```
用户点「取消」→ requestCancel() → cancel_=true
库在 isCancelled() 为 true 时尽快退出 → processHrrp 失败 → failed / finished
```

若弹窗还卡在 `BlockingQueued`，应先关掉对话框（`askCornerConfirm` 返回 false），Worker 才能往下走。

## 8. 文件职责对照表（写代码时的落笔顺序）

推荐你自己重写时的顺序：

1. **CMake** 能链上 SDK 和 Qt，空 `main` 弹出空窗  
2. **SimplePlotWidget** 用假数据画出一条正弦  
3. **ConfirmBridge** 单独在按钮上测弹窗  
4. **DemoWorker::runProbe** + MainWindow 探查按钮（尚可不建线程，验证 API）  
5. **上线程**：moveToThread + Queued invoke + progress  
6. **runPreview** + 预览翻页  
7. **runHrrp** + BlockingQueued 选点 + 画 HRRP  

每一步都能单独编译运行，避免一次堆太多概念。

## 9. 从 HRRP 扩到其它功能

模式完全相同，只换请求/回调/画图数据：

### RCS（二维）

```cpp
RcsRequest req; ...
cb.onCornerPick = ...;   // GrayImage + 全分辨率点
cb.onTargetPick = ...;
processRcs(req, resp, cb, &err);
// 用 resp.targets 或 resp.profileDbsm 展示
```

### 点频

```cpp
CwRcsRequest req; ...
cb.onCornerConfirm = ...;
cb.onTargetPick = ...;
processCwRcs(req, resp, cb, &err);
// 画 freqGHz vs rcsDbsm
```

### 后向散射

```cpp
Sigma0Request req; // rawPath, nr, na, ...
cb.onRectRoi = ...;      // stage: noise / cal / bg
cb.onTargetRois = ...;
// 预览坐标 → 全分辨率：mapPreviewRoiToFull
processSigma0(req, resp, cb, &err);
```

### 大图拼接（SDK 组 [8]）

```cpp
MosaicRequest req;
req.inFolder = ...; req.outFolder = ...;
processMosaic(req, resp, cb, &err);
// resp.mosaicTif / displayTif；预览可用 loadMosaicGrayPreview
```

无人值守批处理时，对应请求设 `autoPick=true` 并预填 ROI/点，可不接选点回调（本 demo 故意接回调，方便学交互）。

## 10. 常见坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 点按钮界面卡住 | 在 UI 线程直接调了 `process*` | 一律 Worker + Queued |
| 选点崩溃 / QWidget 警告 | 在 Worker 线程弹窗 | ConfirmBridge + BlockingQueued |
| `previewDone` 连不上 | 没注册 `PreviewBundle` 元类型 | `main` 里 `qRegisterMetaType` |
| 中文路径乱码 | 用了本地 8bit 路径 | 全程 UTF-8（本 demo 的 `toUtf8`） |
| 找不到 `.so` | 没 pack 或 rpath 不对 | `pack_sdk.sh`；或设 `LD_LIBRARY_PATH` |
| 取消没反应 | 没挂 `isCancelled` | 见 `runPreview` / `runHrrp` |
| 关窗仍卡住 | 阻塞在弹窗或库未退出 | 先关对话框，再 `requestCancel` + `quit` |

## 11. 和正式 GUI / cli_demo 的关系

| 项目 | 关系 |
|------|------|
| `gui/`（本仓库完整界面） | 同一套 SDK 约定，页面更多、Worker 更细；学完本 demo 再看 `gui/modules/*` 会轻松很多 |
| `cli_demo` | 无 Qt；交互用终端问答，部分命令 `autoPick=true` 冒烟 |
| 本 `gui_demo` | **最小可运行的「后台线程 + 阻塞选点 + 自绘曲线」教材** |

## 12. 练习建议

1. 给预览加「只显示当前文件的频谱峰值」到日志（不改库，只改 MainWindow）。  
2. 把 `ConfirmBridge` 改成自定义小对话框，显示建议距离和曲线峰值下标。  
3. 仿 `runHrrp` 加一个「跑点频」按钮（需有点频数据目录）。  
4. 故意去掉 `BlockingQueuedConnection` 改成 `QueuedConnection`，观察卡死/时序错乱，加深理解。

读完源码后，建议再打开 `DemoWorker.cpp` 的 `runHrrp` 与 `MainWindow` 构造函数末尾的 `connect`，对照第 7.3 节时序走一遍，即可上手改甲方自己的壳程序。
