# RCS 处理库接口说明（二次开发）

这份说明对应本目录交付的 `librcs_proc` 动态库。你们拿它做自己的界面软件即可，不需要我们的 GUI 源码。

库本身是 **C++11**，不依赖 Qt。Qt / MFC / Electron 壳子都行，只要能调 C++ 或自己做一层封装。

本包能力范围：

- HRRP 一维距离像：`processHrrp`
- RCS 测量：`processRcs`
- 点频 RCS：`processCwRcs`
- 查版本：`rcsVersion`

**大场景图像拼接不在本次交付里**，头文件里也没有相关声明，请不要按旧文档去找 `processMosaic` 一类接口。

## 1. 目录怎么摆

```text
sdk/
  include/rcs/     头文件
  lib/             librcs_proc.so（及 so 版本软链）
  demo/            命令行小例子，能编过就能说明链接环境 OK
  接口使用说明.md   本文
  README.md        打包说明、怎么编 demo
```

典型链接（Linux）：

```bash
g++ your_app.cpp -I/path/to/sdk/include -L/path/to/sdk/lib -lrcs_proc \
    -Wl,-rpath,/path/to/sdk/lib -pthread -o your_app
```

运行时要把 `librcs_proc.so` 找得到：用 `rpath`，或：

```bash
export LD_LIBRARY_PATH=/path/to/sdk/lib:$LD_LIBRARY_PATH
```

头文件这样包含：

```cpp
#include "rcs/rcs_api.h"
```

## 2. 做界面时建议怎么接

库函数是同步阻塞的：调用后会一直跑到结束（或取消）。界面上千万别在 UI 线程里直接调，否则窗口会卡死。

常见写法：

1. 用户点「开始」→ 工作线程里调 `processHrrp` / `processRcs` / `processCwRcs`
2. `onProgress` / `onMessage` 里用你们框架自己的「切回主线程」手段刷新进度条和日志（Qt 用信号槽，其它框架用 postMessage 一类）
3. 需要人选点时，库会在工作线程里回调 `onCornerConfirm` / `onCornerPick` / `onTargetPick`。回调里要：
   - 切到 UI 线程弹出选点窗口
   - 阻塞等到用户点确定或取消（信号量、条件变量、Qt 的 `QMetaObject::invokeMethod(..., Qt::BlockingQueuedConnection)` 都行）
   - 把选点结果写进传入的 `InteractSelection &`
   - 用户取消则 `return false`，库会当失败退出，错误串一般是「已取消」一类
4. 「取消」按钮把某个 `atomic<bool>` 置位，`isCancelled` 读这个标志返回 `true`

不想交互、先跑通流程时：请求里设 `autoPick = true`，选点回调可以不填。demo 就是这么干的。

同一输出目录不要多路并发写；串行跑，或分不同 `outDir`。

路径：Linux 一般 UTF-8；Windows 上请尽量用宽字符/UTF-8 一致的路径传进来（我们库侧按 UTF-8 处理）。数据目录里要有对应极化的 `*_L0_*.dat`。

## 3. 回调 `Callbacks`

定义在 `callbacks.hpp`。用不到的成员保持默认空即可。

| 成员 | 干什么 |
|------|--------|
| `onProgress(int, string)` | 进度 0～100，后面跟一句当前步骤说明 |
| `isCancelled()` | 返回 true → 尽快停 |
| `onMessage` / `onError` | 日志；错误最终也会从函数返回值和 `err` 里拿到 |
| `onCornerConfirm` | 仅 HRRP：确认角反峰，可改距离（米） |
| `onCornerPick` | RCS：在图上选角反点 |
| `onTargetPick` | RCS / 点频：选目标（点目标或扩展距离段） |

选点回调返回值：`true` 继续，`false` 用户取消。

## 4. HRRP：`processHrrp`

把文件夹里某一极化的 L0 dat 合起来，做脉压、定标，写出 `.hrrp` / `.pdat`，并在 `HrrpResponse` 里带回曲线，方便你们直接画图。

### 请求 `HrrpRequest`

| 字段 | 说明 | 默认 |
|------|------|------|
| `dataFolder` | 原始数据目录（里面有 `*_L0_HH.dat` 这类文件） | 必填 |
| `pol` | 极化，如 `HH` `HV` `VV` `VH` | `"HH"` |
| `tgtName` | 写到文件名里的目标名 | `"目标"` |
| `outDir` | 输出目录；空的话库会在数据目录下建 `处理结果_HRRP_<极化>` | 空 |
| `sigmaTheoryDb` | 角反理论 RCS（dBsm） | `18.25` |
| `cropN` | 距离向裁剪点数 | `8192` |
| `phaseMode` | 相位处理，一般保持 0 | `0` |
| `autoPick` | true：自动用功率峰，不回调 | `false` |

### 响应 `HrrpResponse`

- `rangeM` / `rcsDbsm` / `phaseDeg`：画曲线用
- `hrrpPath` / `pdatPath` / `l1Path`：落盘路径
- `timeSpanTag`：时间标签（文件名里会用到）

### 交互时（`autoPick=false`）

实现 `onCornerConfirm`。参数大致是：距离轴、功率 dB 曲线、自动峰下标。  
若操作员改了距离，把 `sel.cornerRangeOverrideM` 设成新距离（米）；不想改就保持 `<0`。

### 最小例子

```cpp
HrrpRequest req;
req.dataFolder = "/data/batch1";
req.pol = "HH";
req.outDir = "/data/batch1/out_hrrp";
req.autoPick = true;

Callbacks cb;
cb.onProgress = [](int p, const std::string &m) {
    // 刷新进度条
};

HrrpResponse resp;
std::string err;
if (!processHrrp(req, resp, cb, &err)) {
    // 弹错误：err
} else {
    // 用 resp.rangeM / resp.rcsDbsm 画图，或提示打开 resp.hrrpPath
}
```

## 5. RCS：`processRcs`

二维成像链路：脉压、方位压缩、定标，再选角反和目标，写出 `.pdat` / `.rcs`。

### 请求 `RcsRequest`

和 HRRP 类似的字段之外：

| 字段 | 说明 | 默认 |
|------|------|------|
| `azMode` | `1` 条带，`2` 聚束 | `2` |
| `vSar` | 条带时用的平台速度（m/s，按现网习惯填） | `10` |
| `autoPick` | true：角反、目标都走自动逻辑 | `false` |

### 响应 `RcsResponse`

- `targets`：每个目标的 RCS、视角、距离、是否有效、标签等
- `pdatPath` / `rcsPath` / `l1Path`
- `rangeM` / `profileDbsm`：有剖面时会填，可画一维参考曲线

### 交互时

1. `onCornerPick`：给一张灰度预览 `GrayImage`（`pixels` 行优先，宽高见 `width/height`），以及全分辨率 `fullNr`（距离）、`fullNp`（方位）。往 `sel.corners` 里塞 `InteractPick(az, rg)`，**坐标必须是全分辨率下标**，不要用预览图像素下标硬填（预览若有缩放，界面自己做换算）。
2. `onTargetPick`：点目标 → `sel.targetMode=1`，填 `sel.targets`；扩展目标 → `sel.targetMode=2`，填 `extendedRanges`，每段是距离起止（米）。

聚束 / 条带参数和你们操作规程保持一致即可；不确定时先按默认聚束试。

## 6. 点频 RCS：`processCwRcs`

目录里每个频点一个 L0 文件，处理后得到 RCS–频率曲线，并写三级 `.rcs`。

### 请求 `CwRcsRequest`

| 字段 | 说明 | 默认 |
|------|------|------|
| `dataFolder` / `pol` / `tgtName` / `outDir` | 同前 | |
| `sigmaTheoryDb` | 定标体 RCS | `18.25` |
| `targetMode` | autoPick 时：1 点目标，2 扩展 | `1` |
| `autoPick` | 是否跳过交互 | `false` |

### 响应 `CwRcsResponse`

- `freqGHz` / `rcsDbsm`：画 RCS–频率图
- `l3Path`：`.rcs` 路径
- `l1Paths` / `l2Paths`：各级产物列表（若有）

交互时同样会走到目标选点回调（与 RCS 类似，具体以库回调为准）。先 `autoPick=true` 跑通再接界面也不迟。

---

## 7. 返回值、错误、取消

- 函数返回 `false`：失败或取消。若传入了 `err` 指针，里面有可读说明，直接给用户看即可。
- `isCancelled` 返回 true 后，一般会较快退出，`err` 里常见「已取消」。
- 选点回调里不要做特别重的计算；弹窗、画图可以，但别卡死太久不返回。

---

## 8. 输入数据注意点

- 目录里要有对应极化的 L0：文件名一般带 `_L0_HH.dat` 这种片段。
- 输出目录没有的话库会尽量创建；没写权限就会失败。
- 路径里有中文可以，但请保证传入库的是正确的 UTF-8（Qt 上用 `QString::toUtf8()` 再转 `std::string` 比较稳妥）。

## 9. demo 怎么用

```bash
cd demo
cmake -S . -B build -DRCS_SDK_ROOT=..
cmake --build build

./build/rcs_demo
# 只打版本

./build/rcs_demo hrrp  /path/to/数据目录  /path/to/输出目录  HH
./build/rcs_demo rcs   /path/to/数据目录  /path/to/输出目录  HH
./build/rcs_demo cw    /path/to/数据目录  /path/to/输出目录  HH
```

demo 全部 `autoPick=true`，方便在没有界面时验证库和数据是否正常。你们接 UI 时把 `autoPick` 关掉，并实现对应回调。
